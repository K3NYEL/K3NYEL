## Development Philosophy

I prefer learning by building.

When I start a project, I try to understand:

1. How the application should be structured.
2. How the different components communicate.
3. How data should be stored.
4. How the interface should behave.
5. How the application can be maintained and expanded.
6. How the software performs on real hardware.
7. How the project can eventually support multiple platforms.

I'm especially interested in improving projects iteratively instead of treating the first working version as the final version.
